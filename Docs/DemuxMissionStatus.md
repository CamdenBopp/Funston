# Native demux → Apple decoder: evidence and release boundary

This is the implementation status for the source-only GitHub build, not a claim that every Internet Archive original plays. Original Swift in `ArchivePlayerCore` is MIT under the repository `LICENSE`; its package has no third-party dependency. Its optional sibling `ArchivePlayerExtraCodecs` is currently an audit-policy tool, **not** an FFmpeg decoder. Development-only ffprobe/FFmpeg observations are not shipped or linked. The app still prefers AVKit for native MP4/M4V/MOV and offers the new sample-buffer viewer only for MKV.

## System boundary

`ByteSource` (local or bounded HTTP Range) → container `Demuxer` → decoder-ready access units → `CMFormatDescription`/`CMSampleBuffer` → Apple video/audio renderers under one `AVSampleBufferRenderSynchronizer`. The UIKit MKV viewer owns display-layer placement and accessible transport; `CaptionPipeline` follows the synchronizer clock. `SampleBufferFactory` currently makes one explicit copy into CoreMedia-owned memory; it does not claim zero-copy lifetime safety.

The Matroska reader, MPEG program-stream reader with DVD metadata, and MPEG transport-stream reader expose tracks and packets. Their capabilities differ: Matroska's tested AVC/AAC/Opus packets are decoder-ready; raw PS/TS PES packets are **not**. Separate strict PS and TS access-unit adapters are being validated and must not be conflated with the raw demuxers. The engine rejects raw PS/TS to prevent sending arbitrary PES fragments to a decoder.

## Next experiments that decide the gaps

1. Run the actual decode and visible-window playback gates on the owner's iPhone 14 Pro Max (signing now works), listen to each track, use VoiceOver to choose tracks/captions/seek/close, and measure frame presentation and A/V drift rather than inferring from renderer status.
2. Broaden the bounded AVC access-unit reassembly beyond AUD-marked TS, then measure seek and displayed-frame/drop behavior. The tested real TS crosses PES boundaries and rendered on Mac; if another stream lacks AUD, test slice-header-based boundaries rather than guessing one PES equals one frame.
3. Validate PS adapter against full multi-VOB DVD sets, IFO time maps, LPCM and subpictures. Repeat the exact VOB decoder gate on physical iPhone; if MPEG-2 remains unavailable, either leave that track unsupported in the MIT core or implement and audit the separate optional LGPL fallback.
4. Build a visible-window test and an audio-output tap for the independent MKV audio switch. Its measured compressed-packet handoff is not an acoustic gap or proof of hitch-free video; compare displayed-frame timestamps and a switch-local drop baseline.
5. For bitmap PGS/VobSub and CEA-608/708, build bounded extraction/decoding tests on real named IA items and a VoiceOver text equivalent. The existing text caption pipeline and narrow CEA-608 state machine alone do not satisfy this.
6. Run matched cold-cache, release-build sample-buffer and Swift-native remux/HLS alternatives on the same files and devices. The current FFmpeg command is a development oracle, not a shippable remux implementation or a fair CPU ranking.

The codec/container observations above rely on live IA metadata URLs and the per-module findings, which cite Apple APIs, container specifications and exact tests. Synthetic tests are identified as such in those findings. A result not reproduced on the physical device remains a question, not a compatibility promise.

Coordinated verification on 2026-09-27: `swift test --package-path ArchivePlayerCore -j 2` passed **87 tests, 17 opt-in skips, zero failures**; `swift test --package-path ArchivePlayerExtraCodecs -j 2` passed **four tests, zero failures**; the full iPhone 16 Pro simulator `ArchiveTests` suite passed **64 tests, two live-test skips, zero failures**. A separate opt-in simulator run passed the live TS renderer gate plus 16 UI presentation tests (**17 passed, no skips/failures**). An opt-in `ArchiveUITests.testOriginalMKVAudioTrackJourneyIfEnabled` passed on the simulator after correcting its post-dismiss assertion to expect the file picker, not the underlying artifact; it does not substitute for manual VoiceOver testing. The reusable package source and app build remain uncommitted workspace changes; no device release artifact or GitHub push was created by this mission.
