# Matroska / WebM demuxer findings

Implemented from primary specifications, without third-party demuxer source code:

- EBML variable integers, unknown sizes, bounds: https://www.rfc-editor.org/rfc/rfc8794.html
- Element IDs, track fields, defaults: https://www.matroska.org/technical/elements.html
- Block layout, signed timestamps, Xiph/fixed/EBML lacing: https://www.matroska.org/technical/notes.html

The actor reads headers on demand and only materializes individual payloads (32 MiB configurable default cap). Short ByteSource reads are accumulated. Unknown-size Segments and Clusters are supported. Tracks must precede the first Cluster. Track identifiers, codec names/private data, language, name, channel count and selected accessibility roles are surfaced. Blocks and SimpleBlocks split all three lace forms into separate packets. DefaultDuration or BlockDuration supplies laced frame timing; missing timing produces an explicit unsupported error. DTS remains invalid because block ordering alone cannot establish it.

Synthetic EBML fixtures cover track discovery, signed timestamp offsets, all lacing forms, unknown Cluster size and transitions, BlockGroup reference/keyframe behavior and duration, CodecDelay, malformed fixed lacing, truncated payloads, and rewind. Their source intentionally returns at most three bytes per read.

The opt-in live Range test (`IA_NETWORK_TESTS=1 swift test --filter MatroskaTests`) validates IA item `the-ancient-magus-bride-s-01-e-03-720p-hd-blu-ray-multi-audio-esub`, file `The Ancient Magus' Bride S01E03 720p HD BluRay Multi Audio ESub.mkv` (169,641,007 bytes according to its metadata). [IA metadata](https://archive.org/metadata/the-ancient-magus-bride-s-01-e-03-720p-hd-blu-ray-multi-audio-esub). On 2026-09-27, track discovery read 4,097 bytes and returned six tracks: H.264, Hindi AAC, English Opus, Japanese Opus, and two English PGS subtitle tracks. An independent `ffprobe -probesize 32768 -analyzeduration 0 -show_entries stream=index,codec_name,codec_type:stream_tags=language` invocation against the same URL confirmed this list. The live fixture is fetched with Range; it is not vendored or downloaded in full.

Seeking uses SeekHead's Cues location when available, choosing the video track's preceding cue (or the first track for audio-only files). Without usable Cues, a header-only scan indexes Cluster timestamps and skips known-size payloads. The scan limits outer/Cluster header traversal to 100,000 headers; metadata child lists are separately limited to 100,000 entries. Cue offsets are checked against Segment bounds and the target must be a Cluster. Indexes are retained for subsequent seeks. The sparse fallback lands at a preceding Cluster; it does not guarantee that the Cluster begins with a video keyframe. CueRelativePosition and CueBlockNumber are not consumed, so decoder preroll and dropping samples before the desired presentation time remain caller responsibilities.

On 2026-09-27, seeking the IA fixture to 300 seconds took 7.76 seconds including obtaining the first packet, transferred 56,782 bytes during index construction/seek, and returned first PTS 298.9145 seconds. This used a deliberately small 4 KiB HTTP read-ahead window and is one observed network run, not a latency guarantee. The same live test successfully demuxed the first 32 packets and built native H.264 and AAC CMFormatDescriptions using the real track CodecPrivate fields. Ten Matroska tests passed with network tests enabled; synthetic seek tests exercise both Cues and a missing-Cues unknown-Cluster sparse fallback.

Limitations: ContentEncodings (including header stripping/encryption), TrackTimestampScale and DiscardPadding are explicitly unsupported. CodecDelay is subtracted from packet PTS. No codec decoding or codec-specific duration inference is performed. EBML CRCs are not verified. The real fixture establishes demux and format-description compatibility, not decoded playback compatibility. Concurrent method calls should be serialized by the caller because actor suspension during source reads permits reentrancy.
