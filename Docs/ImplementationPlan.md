# Internet Archive — Native Media Client

## Product contract

Support complete journeys through real Internet Archive artifacts: discover or search, understand provenance, play supported audio while browsing, save items, download files, and resume later. Artwork-led collection shelves and illustrated result rows make discovery visible. Supported PDFs open in a native PDFKit reader with text search, saved page position, and an automatic on-device recognized-text view for scanned pages; compatible films open in AVKit. Restricted and unsupported artifacts retain normalized identity, description, provenance, file inspection and an external Archive link. EPUBs open in a native reader. Expanded reader capabilities remain later work.

The three persistent destinations are Explore, Search, and Library; Library filters between all, saved, and downloaded items. iPhone uses the system tab bar with an independent navigation stack per destination. iPad adapts to a native split view. Artifact detail is a push destination from any collection. LNPopupController presents a native compact player whenever audio is loaded and opens the app-owned SwiftUI full player interactively; the app retains ownership of playback state and transport actions.

On iPad, a three-column split view owns one sidebar containing the three destinations, a secondary column containing that destination's collection or result history, and an optional detail column containing the selected artifact. Compact-width collapse restores the corresponding destination's navigation stack rather than inventing a second routing model. One app-scoped player presentation follows the active tab or split container; LNPopupController owns docking and safe-area adjustments. Container changes preserve whether the player was expanded.

Explore presents a small verified directory of real Archive collections and their live contents. It does not fabricate recommendations, metrics, counts, or personalization. Search uses a native search field with a visible media scope and retains query, filters, results, scroll position, and paging state across navigation.

Artifact detail has two layers:

1. Artifact: artwork, full title, creator/date when present, a truthful primary action, tracks when meaningful, description, provenance, and collection relationships.
2. Inspector: identifier, originals, derivatives, images, metadata files, sizes, formats, and Archive links.

Missing values disappear rather than becoming filler. Uncertain dates and rights remain uncertain. Restricted or unsupported media never receives a false Play action.

Saving, downloading, and playback progress are independent. Library contains explicitly saved artifact snapshots; removing one does not delete its downloads or progress. Removing a download does not unsave the artifact or erase progress. A local file currently in use is marked unavailable to new playback immediately but physical deletion waits until the player releases it.

Playback is track-based. Selecting a track loads that track and end-of-track advances to the next playable track in the artifact. Logical order uses valid disc and track metadata first, placing numbered tracks before unnumbered ones; conflicting or missing values fall back to a locale-independent natural comparison of exact file names with the file name as the final tie-breaker. Exhausting playable tracks ends playback rather than wrapping. Resume positions are keyed by the stable pair of artifact identifier and exact Archive file name. A relaunch restores the most recent item, track, position, and paused state but never autoplays. A track's ordinary menu and the player provide Download/Remove Download; the artifact action can download its currently selected preferred track without implying that all files were downloaded.

## Architecture contract

- iOS 18 minimum, Swift 6 strict concurrency, iPhone and iPad. Apple frameworks provide rendering, media engines, networking and persistence. LNPopupController 4.5.12 is a focused MIT-licensed presentation dependency, vendored at an exact revision with an explicit-header-path manifest patch; runtime source is unchanged. Its MIT-licensed LNSystemMarqueeLabel dependency is locked to 0.1.2. See [ComponentDecisions.md](ComponentDecisions.md) for researched alternatives, integration tradeoffs and licensing, and [vendored provenance](../Vendor/LNPopupController/PROVENANCE.md) for revision and checksums.
- UIKit owns large paginated collections, reused cells, search-controller behavior, and performance-sensitive scrolling. SwiftUI owns bounded detail sections, state-driven empty/error surfaces, player composition, and small forms. Bridge at screen boundaries, not per metadata field.
- A single app container owns networking, persistence, downloads, artwork, and playback. Immutable normalized domain values are independent of either UI framework.
- Explicit state machines separate content from refresh, paging, playback, and transfers. Cached content stays visible during refresh failure. Cancellation never becomes an error.
- Durable cache entries live in SQLite as compressed response blobs plus normalized snapshots. Search-page keys are the canonical query, scope, sort, and page; metadata keys are the exact identifier. A cached zero-result page is a valid response distinct from a cache miss. Search pages are fresh for 15 minutes and metadata for 24 hours, after which they render as stale while revalidation runs. One access-time LRU caps the combined compressed-response and normalized-snapshot representations at 50 MB and evicts both records for a key together; durable Library snapshots and downloads are not part of that eviction budget.
- Internet Archive endpoints in this slice: advanced search, metadata, file delivery, and item thumbnail. Plain search input is escaped; it is not silently treated as raw Archive query syntax.
- Decode and normalize off the main actor. Search uses cancellation, a short debounce, request generations, stable identifiers, deduplication, and at most one in-flight page.
- Normalize permissive string/array/number fields once. A non-main-actor normalization service creates the track and inspector models before UI publication. UIKit owns reused/lazy track and file collections as well as search results; no SwiftUI detail section materializes thousands of rows. Grouping is precomputed once per metadata payload and rendering never rescans the full file list.
- Audio resolution uses metadata only and never probes every remote asset. It first evaluates item-level access metadata: confirmed restriction disables streaming, unknown availability remains a distinct unresolved capability, and absence of restriction permits file resolution. It then reads exact `name`, `format`, `source`, `original`, `private`, and size fields; excludes private, metadata, spectrogram, and unsupported entries; groups a derivative by its exact `original` name; and orders each group deterministically by completed local file, VBR/standard MP3 or M4A, original compatible audio, then lower-bitrate MP3. File name breaks ties. Playback may try the next already-ranked candidate after a concrete AVPlayer failure, and the Files/Quality UI keeps every candidate explicit.
- Artwork uses ImageIO downsampling, keyed in-flight work, bounded fetch/decode concurrency, cost-limited decoded memory caching, URLCache for compressed responses, reuse cancellation, and memory-warning eviction.
- Playback is app-scoped and owns one AVPlayer, audio-session lifecycle, interruption/route handling, remote commands, Now Playing metadata, local-file preference, observer cleanup, and coarse durable progress. Elapsed time updates only visible player controls; there is no idle timer.
- A dedicated `SQLiteStore` actor, never isolated to the main actor, owns the synchronous connection, prepared statements, and transactions. A separate normalization actor owns large metadata transforms. UI controllers await small immutable results and never inherit database or normalization work onto the main actor.
- SQLite stores cached responses, saved snapshots, playback positions, and durable download records with prepared statements, transactions, migrations, stable keys, and focused observations. Redownloadable media is excluded from backup.
- Physical-device downloads use a named background URLSession and the stable `(identifier, exact file name)` key in both durable records and task descriptions. Simulator builds use an in-process session because the tested runtime's background-transfer daemon failed; see [SimulatorDownloads.md](SimulatorDownloads.md). Duplicate requests coalesce. Delivery URLs percent-encode each path segment. Local paths are derived from a SHA-256 of the stable key and transfer-attempt identity plus a safe extension, never from a remote path. Delegate handling validates 2xx HTTP status and the expected byte count when Archive supplied one, moves the temporary file before the callback returns, then commits completion. Relaunch reconciliation promotes a moved file whose record was not committed, marks a completed record missing when its file vanished, rejoins live tasks, and removes unreferenced orphan files. Disk-full and integrity failures retain a retryable failed record. A serial delegate queue and explicit asynchronous operation chain preserve event order; the application acknowledges the background-session completion handler only after persistence work drains.

## State and accessibility contract

Search distinguishes initial, searching, loaded, loading-more, empty, cached/stale, offline, and failure-with-or-without-content. Detail keeps its summary while metadata enriches or fails. Playback explicitly represents idle, preparing, playing, paused, buffering, ended, and failed. Transfers represent queued, downloading, completed, failed, and cancelled.

Search, explore, and library rows are one navigation element with a concise combined identity. Secondary commands use menus/context menus and equivalent accessibility actions. Artwork is hidden when redundant. Missing metadata is omitted from speech. The compact player contains two distinct stops: Open Player and Play/Pause.

The full player's position control is adjustable, exposes localized “elapsed of total” text, and moves by a clamped 15 seconds per accessibility increment. Track identity and Playing, Paused, Buffering, or Failed state are spoken without relying on artwork or color. User-initiated preparation failure produces one concise accessible announcement and leaves the failed track selected; routine buffering and time changes do not announce. All transport targets retain at least a 44-point effective area. At accessibility text sizes, the compact player grows vertically: Open Player retains the full title on its own flexible line and Play/Pause remains a separate trailing control.

Large Dynamic Type may stack metadata and actions, grow rows, and place the position control on its own line. Essential content is never shrunk to preserve a screenshot. Status combines text or symbols with color. System motion is preferred; custom motion must respect Reduce Motion. Custom materials, if introduced, must respect Reduce Transparency.

VoiceOver focus follows conceptual reading order and does not jump when results or progress update. Routine download percentages are values, not announcements. Sheet dismissal returns focus to its initiating control when practical. Test identifiers remain separate from spoken labels.

Library mutations become visible only after a successful database transaction. A failed save/remove preserves the prior state and presents a focused inline error with Retry without clearing content. Remove from Library offers Undo using the retained snapshot. Cancelling a transfer keeps a restartable record; Retry is available for network, storage, integrity, and missing-local-file failures. Essential save, download, and retry operations have ordinary visible controls; menus and accessibility custom actions are accelerators, not the only route.

## Deferred work

Document-wide OCR search, richer PDF annotations and video workflows, Wayback, radio mode, iCloud, Spotlight, SharePlay, custom time browsing, custom rotors, rich provenance timelines, and personalized recommendations are later slices. CarPlay audio browsing and playback are implemented; device entitlement setup and head-unit verification are described in [CarPlay.md](CarPlay.md). EPUB reading and App Intents are implemented. The existing PDFKit reader, page-by-page on-device OCR view, and AVKit playback are part of the current app. OCR defaults to an automatic no-prompt route, while a remembered Reading Options preference and engine registry preserve user choice and future extensibility.

## Acceptance gates

- A real live-data search result can open, play, save, download, relaunch, and play locally without fixture-only shortcuts.
- Playback continues while the user changes tabs and explores another artifact.
- Query, filters, results, selection, navigation, and scroll context remain stable.
- Long and non-Latin text, absent and malformed metadata, one and thousands of results, a 4,000-file item, no matches, 429 responses, offline cache, interrupted download, and unavailable audio all produce coherent states.
- No decoding, file normalization, date parsing, or image decompression occurs during main-thread row configuration.
- No app-owned repeating work runs while idle. Playback progress persists on meaningful events and a coarse interval, not every tick. Download UI is coalesced.
- Unit tests cover query encoding, permissive decoding, file grouping, stale-response rejection, persistence migrations/transactions, and download recovery. Injected transports and temporary filesystems deterministically produce delayed/out-of-order pages, cached empty results, 429 with Retry-After, offline relaunch, disk full, post-move/pre-commit interruption, missing local files, and retry. Deterministic UI tests cover search-to-save, cross-tab playback, offline cached browsing, and failed-download retry. A separate live Archive smoke run proves endpoint compatibility but never substitutes for deterministic correctness.
- VoiceOver completes the primary workflow; important elements have correct roles, labels, values, state, actions, and order. Largest accessibility sizes remain operable. Accessibility Inspector, Bold Text, Increase Contrast, Differentiate Without Color, Reduce Motion, Reduce Transparency, Voice Control, light/dark appearance, and iPad layout are checked.
- Performance is measured in a Release build with signposts. The documented physical reference is an iPhone 15 Pro or the team's named replacement on the oldest supported iOS; simulator evidence is recorded separately. Scenarios are: warm cached search presentation, a 40-row fast scroll, open/back repeated ten times, normalization of a 4,000-file fixture, and 30 seconds paused on an idle screen. Targets: cached snapshot visible within 100 ms of view appearance; row configuration p95 below 4 ms with no synchronous decode/parse; 4,000-file normalization below 250 ms off-main; retained resident memory after the tenth cycle no more than 10 MB above the post-second-cycle baseline; idle app-owned CPU below 1% with zero repeating app timers. Cold network latency is recorded, not treated as an app performance pass/fail.

Physical-device Instruments, background transfer, audio interruption, and manual VoiceOver checks cannot be closed by simulator-only automation; any unrun gate remains explicitly recorded.
